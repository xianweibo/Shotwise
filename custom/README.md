# Paul's Mod Layer (Shotwise fork)

Upstream: https://github.com/ghc4412/Shotwise (AGPL-3.0)
This fork: https://github.com/xianweibo/Shotwise

## Goal

Keep every local modification alive across upstream releases. Three layers of protection:

1. **Branch `paul/main`** - mods live as real git commits on top of the pinned upstream baseline.
   History is never rewritten; `git log paul/main` is the source of truth.
2. **`custom/patches/*.patch`** - every mod exported with `git format-patch`.
   Used to rebuild the mod layer on a brand new upstream baseline when a plain merge is not enough.
3. **`custom/PATCHES.md`** - human registry. One row per mod: why, what, which files, how to verify.

Upstream work that arrives after `main` is merged / rebased in, so both histories stay visible.

## Layout

```
custom/
  README.md            <- this file
  PATCHES.md           <- registry, update it whenever a mod lands
  patches/
    0001-*.patch       <- generated by scripts/export_mods.ps1
  scripts/
    sync_upstream.ps1  <- fetch upstream + merge into paul/main (reports conflicts, never guesses)
    rebuild.ps1        <- rebuild paul/main from an upstream ref and git-am all patches
    export_mods.ps1    <- regenerate patches/ from commits touching Paul's area
```

## Rules

- Never commit on `main` of this fork. `main` only fast-forwards from upstream.
- Every mod gets a row in `PATCHES.md` **and** a commit whose message starts with `zyt(mod):`.
- `.ps1` files are ASCII-only. PowerShell 5.1 reads scripts as ANSI; UTF-8 Chinese comments get garbled.
- No secrets in this repo ever. Console password / tokens stay in env or on-NAS config.

## Routine

```powershell
# 1. take upstream updates
.\custom\scripts\sync_upstream.ps1

# 2. if the merge is hopeless (upstream rewrote the file), rebuild instead
.\custom\scripts\rebuild.ps1 -UpstreamRef v0.29.0

# 3. after adding a mod by hand
.\custom\scripts\export_mods.ps1
```
